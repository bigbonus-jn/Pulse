## 产品定位

- **一句话**：让普通用户也能一键把小组件钉在桌面上，零配置开箱即用
- **目标用户**：Windows 11 主流用户（非极客），希望桌面信息展示但不想折腾 Rainmeter
- **首发品类**：系统监控（CPU仪表盘、内存条等）
- **选择理由**：刚性强 + 开发成本低（本地API） + 价值可感知（数字实时跳动）

## 市场调研核心结论

### 市场三层结构

| 层级 | 代表 | 特点 | 痛点 |
|------|------|------|------|
| 官方 Widget Board | 内置小组件 | Adaptive Cards、系统级集成 | 浮出面板，无法驻留桌面 |
| 开源社区 | Rainmeter | 2.4MB 极小、0.1-1% CPU、完全桌面驻留 | 技术门槛高，与官方生态脱节 |
| 商业应用 | Widget Launcher | Freemium 模式 | Electron 方案内存 80-150MB |

### 用户核心痛点（按优先级）

1. **桌面驻留缺失**（最高优先级）：Widget Board 为浮出面板，微软无开放桌面级 API 计划
2. **MSN 资讯流侵入性**：2026年5月微软已默认隐藏（"春季清理"）
3. **悬停自动打开**：已默认关闭
4. **第三方选择少**：Widget Board 中第三方小组件数量稀少

### 技术路线关键结论

- **WebView2 轻量封装是 MVP 最优选择**：系统内置运行时，30-60MB 内存，不依赖 Store 分发
- **WinAppSDK + Adaptive Cards**：进入官方生态的唯一正门，但受限于浮出面板 + 声明式 UI
- **Web Widget Providers**：已突破 Adaptive Cards 限制支持 HTML 渲染，但目前仅 EEA 地区
- **微软无开放桌面级 API 计划**：桌面驻留需求真空将长期存在

### 机遇窗口

微软"春季清理"收缩过度商业化功能，同时第三方小组件在 Widget Board 中数量稀少，先发者可获得不成比例的官方曝光。未来 12-18 个月为最佳切入窗口。

## MVP 技术架构

```
┌─────────────────────────────────────────────┐
│              C# / WinUI 3 宿主进程           │
│  ┌─────────┐  ┌──────────┐  ┌───────────┐  │
│  │ 窗口管理 │  │ 托盘图标  │  │  自启动    │  │
│  └────┬────┘  └──────────┘  └───────────┘  │
│       │ Win32 API (无边框透明/置顶/拖拽)     │
│  ┌────┴────────────────────────────────────┐ │
│  │         WebView2 (Edge) 渲染引擎         │ │
│  │  ┌─────────────────────────────────┐    │ │
│  │  │     HTML + CSS + JS 小组件 UI    │    │ │
│  │  │  (圆形仪表盘/进度条/卡片)        │    │ │
│  │  └─────────────────────────────────┘    │ │
│  └─────────────────────────────────────────┘ │
│       │ PostWebMessage 双向通信               │
│  ┌────┴────────────────────────────────────┐ │
│  │  C# System.Diagnostics 数据采集          │ │
│  │  (CPU/内存/温度/网速)                    │ │
│  └─────────────────────────────────────────┘ │
│       │ JSON 配置文件                         │
│  ┌────┴────────────────────────────────────┐ │
│  │  持久化：用户布局/大小/位置记忆          │ │
│  └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

### 核心交互流程

宿主进程启动 → 创建无边框透明 WebView2 窗口 → 加载本地 HTML 小组件页面 → C# 定时采集系统数据 → 通过 PostWebMessage 推送至 JS → JS 更新前端 UI 动画

## 三阶段执行计划

### Phase 1：MVP 验证（0-3 周）

**Week 1：基础框架**
- 搭建 C# WinUI 3 宿主进程项目骨加
- 实现无边框透明 WebView2 窗口创建
- 实现窗口拖拽、置顶、点击穿透
- 系统托盘图标实现（右键退出、显示/隐藏）

**Week 2：CPU 仪表盘小组件**
- C# 后端采集 CPU 占用率数据（PerformanceCounter）
- 前端圆形仪表盘组件（Canvas/SVG 绘制）
- WebView2 双向通信调通（C# ↔ JS）
- 实时数据推送与 UI 刷新（1秒间隔）

**Week 3：集成测试与社区发布**
- 布局持久化：位置/大小记忆（JSON 配置）
- 整体测试与 Bug 修复
- GitHub 开源发布 + 社区推广（V2EX、小众软件等）
- 收集用户反馈，判断需求验证信号

### Phase 2：产品化（3-6 个月）

- 扩充小组件品类：内存占用、时钟、天气、快捷启动器
- 主题市场上线：免费基础皮肤 + 付费高级主题
- 自动更新机制、多小组件实例管理
- Freemium 变现测试

### Phase 3：双轨矩阵（6-12 个月）

- WinAppSDK + Adaptive Cards 进 Widget Board，作为品牌曝光和获客渠道
- 引导用户下载功能更完整的独立版
- 监测 Web Widget Providers 全球开放进度，一旦可用即升级官方版体验

## MS Store 政策要点（v7.19, 2025.10.14 生效）

- 必须提供隐私政策 URL
- 个人信息收集需用户明确选择加入
- 广告必须与内容明确区分
- 禁止远程脚本执行违反声明的功能
- **关键利好**：PC 非游戏产品可使用第三方购买 API 或 Store 内购 API
